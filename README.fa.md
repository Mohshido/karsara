## کارسرا چیست؟

کارسرا متن فایل‌های PDF متنی را استخراج می‌کند تا بتوانید آن را ویرایش کنید، با صدای فارسی بشنوید و به‌صورت TXT یا سند Word ذخیره کنید. رابط برنامه فارسی و راست‌به‌چپ است و از کنترل با صفحه‌کلید و بازیابی پیش‌نویس محلی پشتیبانی می‌کند.

پردازش سند و تولید گفتار روی دستگاه شما انجام می‌شود. مدل صدای فارسی همراه پروژه است؛ بنابراین استفادهٔ روزمره به سرویس ابری یا کلید API نیاز ندارد.

## وضعیت پروژه

**کارسرا یک محصول اولیه (MVP) در حال توسعه است.** هدف فعلی بستهٔ نصب، ویندوز است. گردش‌کار خودکار ویندوز شامل آزمون‌های رگرسیون، آزمون یکپارچهٔ Electron و ساخت بستهٔ نصب است. نشان بالای صفحه وضعیت فعلی این بررسی‌ها را نمایش می‌دهد.

اجرای توسعه و آزمون گردش‌کار بسته‌بندی‌شده در لینوکس نیز بررسی شده است؛ این به معنی انتشار رسمی برای لینوکس یا macOS نیست. رفتار صفحه‌خوان، پخش از دستگاه صوتی واقعی و اجرای نسخهٔ نصب‌شده در ویندوز همچنان به آزمون پیش از انتشار نیاز دارند. دسترس‌پذیری هدف طراحی پروژه است و به معنای دریافت گواهی انطباق نیست.

## نصب و توسعه

### پیش‌نیازها

- **Node.js 24 LTS** و npm؛ همین نسخه در CI استفاده می‌شود.
- Git، محیط دسکتاپ گرافیکی و خروجی صوتی برای شنیدن صدا.
- اینترنت برای نصب اولیهٔ وابستگی‌ها؛ Electron و کتابخانه‌های بومی متناسب با سیستم در این مرحله دریافت می‌شوند.
- ویندوز برای ساخت و بررسی بستهٔ نصب ویندوز.

### اجرا از روی کد

<div dir="ltr">

```bash
git clone https://github.com/alihd-tech/karsara.git
cd karsara
npm ci
npm start
```

</div>

برای بازتولید وابستگی‌های مورد استفاده در CI، از npm و فایل ثبت‌شدهٔ `package-lock.json` استفاده کنید. پوشهٔ مدل باید کامل باقی بماند:

<div dir="ltr">

```text
models/vits-piper-fa_IR-ganji-medium/
├── fa_IR-ganji-medium.onnx
├── tokens.txt
├── espeak-ng-data/
└── MODEL_CARD
```

</div>

### ساخت بستهٔ نصب ویندوز

در ویندوز، پس از اجرای `npm ci`:

<div dir="ltr">

```bash
npm run build
```

</div>

بستهٔ نصب NSIS در پوشهٔ `dist/` ساخته می‌شود. مدل گفتار به‌صورت منبعی خارج از آرشیو برنامه و کتابخانه‌های بومی گفتار به‌صورت بازشده بسته‌بندی می‌شوند. این فرمان نسخه‌ای را به‌صورت عمومی منتشر نمی‌کند. ساخت را در ویندوز انجام دهید تا وابستگی‌های بومی با سیستم مقصد یکسان باشند.

## روش استفاده

1. یک PDF متنی انتخاب کنید یا روی محل دریافت فایل رها کنید و سپس **افزودن** را بزنید.
2. متن استخراج‌شده را در ویرایشگر مرور کنید. در صورت نیاز، متن را تغییر دهید، جهت نوشتار را تنظیم کنید یا اصلاح پیشوندهای فارسی را اجرا کنید.
3. برای شنیدن بخشی از متن، آن بخش را انتخاب کنید. اگر انتخابی وجود نداشته باشد، کل متن خوانده می‌شود. دکمهٔ توقف، تولید یا پخش گفتار را لغو می‌کند.
4. **مرحله بعد** را بزنید و خروجی TXT یا DOCX را از پنجرهٔ ذخیره‌سازی دریافت کنید.
5. پس از ذخیره، با **نمایش فایل ذخیره شده** محل فایل را باز کنید.

ویرایش‌ها پس از مکثی کوتاه به‌صورت محلی ذخیره می‌شوند. در اجرای بعدی، **ادامه ویرایش** را انتخاب کنید. جایگزینی پیش‌نویس فعلی با PDF جدید به تأیید شما نیاز دارد. اگر ذخیره کامل نشده باشد، هنگام خروج می‌توانید در برنامه بمانید یا تغییرات ذخیره‌نشده را کنار بگذارید.

<a id="shortcuts"></a>

### میانبرهای صفحه‌کلید

میانبرها زمانی فعال‌اند که برنامه در کانون باشد. دسترسی به هر فرمان به صفحهٔ فعلی بستگی دارد.

| میانبر | عملکرد | محل استفاده |
| --- | --- | --- |
| `Ctrl + Shift + O` | انتخاب PDF | همهٔ صفحه‌های اصلی |
| `Ctrl + Shift + P` | خواندن متن انتخاب‌شده یا کل متن | ویرایشگر |
| `Ctrl + Shift + Q` | توقف گفتار | ویرایشگر |
| `Ctrl + Shift + V` | چسباندن با اصلاح پیشوندها و سپس خواندن | ویرایشگر |
| `Ctrl + Shift + W` | خروجی DOCX | ویرایشگر و صفحهٔ خروجی |
| `Ctrl + Shift + L` | خروجی TXT | ویرایشگر و صفحهٔ خروجی |

فرمان‌های معمول ویرایش و بازگردانی تغییرات نیز در ویرایشگر در دسترس‌اند. این میانبرها در سطح کل سیستم ثبت نمی‌شوند.

## حریم خصوصی و ذخیره‌سازی محلی

- استخراج متن PDF، ویرایش، خروجی سند و تولید گفتار به‌صورت محلی انجام می‌شوند. گردش‌کار فعلی سند شما را به سرور ارسال نمی‌کند.
- PDF فعلی و متن ویرایش‌شده برای بازیابی در IndexedDB نمایهٔ برنامه ذخیره می‌شوند و پس از بستن برنامه باقی می‌مانند. این فضا گاوصندوق رمزگذاری‌شدهٔ اسناد نیست.
- صدای تولیدشده در حافظه نگهداری می‌شود. فایل‌های WAV موقت تولیدشده توسط نسخه‌های قدیمی برنامه هنگام شروع پاک‌سازی می‌شوند.
- فایل‌های خروجی TXT و DOCX در محلی که انتخاب می‌کنید باقی می‌مانند.

## محدودیت‌ها و موارد تکمیل‌نشده

| مورد | وضعیت فعلی |
| --- | --- |
| اندازهٔ PDF | حداکثر **۲۵ مگابایت دودویی (MiB)** برای هر فایل |
| متن استخراج‌شده یا خروجی | حداکثر **۲٬۰۰۰٬۰۰۰ واحد رشتهٔ جاوااسکریپت**؛ بیشتر حروف فارسی یک واحد هستند |
| پردازش گفتار | قطعه‌های حدوداً هزارنویسه‌ای؛ مهلت دو دقیقه برای هر درخواست پردازش |
| PDF اسکن‌شده | به OCR نیاز دارد که در برنامه موجود نیست |
| چیدمان PDF | حفظ دقیق صفحه‌آرایی، ساختار جدول‌ها یا ترتیب بی‌نقص خواندن تضمین نمی‌شود |
| ظاهر فایل Word | قلم `B Nazanin` درخواست می‌شود؛ ظاهر نهایی به قلم‌های نصب‌شده در سیستم دریافت‌کننده بستگی دارد |
| اسناد کاری | یک سند و پیش‌نویس جاری؛ بدون کتابخانهٔ چندسندی یا همگام‌سازی ابری |

اگر متنی پیدا نشود، برنامه نیاز به OCR را توضیح می‌دهد. همچنان می‌توانید متن را به‌صورت دستی در ویرایشگر وارد کنید.

## آزمون‌ها و CI

<div dir="ltr">

```bash
npm test
npm run test:smoke
```

</div>

- **آزمون‌های رگرسیون:** اعتبارسنجی PDF، حفظ متن فارسی، ساخت WAV، ثبت یا شکست تراکنش پایگاه داده، هش سبک‌های CSP با پایان‌خط‌های متفاوت، اعتبارسنجی فرستندهٔ IPC، لغو پردازش و تداخل عملیات پخش.
- **آزمون یکپارچهٔ Electron:** انتخاب و استخراج PDF، اصلاح متن، ذخیره و بازیابی، تولید و لغو گفتار و خروجی TXT و DOCX در نمایهٔ موقت جداگانه.
- **CI ویندوز:** نصب وابستگی‌های قفل‌شده، اجرای هر دو مجموعه آزمون و ساخت بستهٔ نصب. جزئیات در [گردش‌کار بررسی برنامه](.github/workflows/checks.yml) آمده است.

آزمون یکپارچه به محیط گرافیکی نیاز دارد. در لینوکس، با نصب Xvfb:

<div dir="ltr">

```bash
xvfb-run -a npm run test:smoke
```

</div>

پیش از انتشار، نسخهٔ نصب‌شده را روی ویندوز تمیز، بدون اینترنت، با NVDA، ناوبری فقط با صفحه‌کلید، بزرگ‌نمایی، کنتراست بالا و دستگاه صوتی واقعی بررسی کنید. [گزارش رفع ایرادها](FIXES.md) تاریخچهٔ بررسی‌ها و موارد باقی‌مانده را توضیح می‌دهد. تعداد آسیب‌پذیری‌های وابستگی‌ها در آن گزارش مربوط به زمان بررسی است و تضمین امنیت زنده محسوب نمی‌شود.

## معماری پروژه

| فایل یا پوشه | مسئولیت |
| --- | --- |
| `main.js` | چرخهٔ پنجره، IPC معتبر، پنجره‌های انتخاب و ذخیرهٔ فایل، خروجی‌ها و مدیریت پردازشگر |
| `preload.js` | پل محدود میان رندرکنندهٔ ایزوله و پردازش اصلی |
| `processor.js` | استخراج PDF و تولید گفتار در پردازش‌های کمکی جداگانه |
| `shared.js` | ذخیره‌سازی تراکنشی IndexedDB، اعتبارسنجی ورودی و اصلاح پیشوند فارسی |
| `uploadFile.html` / `uploadFile.js` | صفحهٔ انتخاب فایل و ادامهٔ پیش‌نویس |
| `editor.html` / `editor.js` | ویرایش متن، ذخیرهٔ خودکار و پخش صدا |
| `workSpace.html` / `workSpace.js` | صفحهٔ خروجی TXT و DOCX |
| `validation.js` / `wav.js` | اعتبارسنجی ورودی در پردازش اصلی و ساخت WAV در حافظه |
| `accessibility.css` | سبک‌های مشترک نمایش کانون و کنتراست بالا |
| `models/` | مدل فارسی، توکن‌ها، داده‌های eSpeak و کارت مدل |
| `tests/` | آزمون‌های رگرسیون و یکپارچهٔ Electron |

فناوری‌های اصلی Electron، جاوااسکریپت، HTML/CSS، بستهٔ `pdf-parse`، موتور `sherpa-onnx-node` و کتابخانهٔ `docx` هستند. برنامهٔ فعلی به چارچوب فرانت‌اند یا سرور بک‌اند نیاز ندارد.
